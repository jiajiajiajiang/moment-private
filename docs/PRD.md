# 片刻 Moment — 产品需求文档

> 版本：1.0  
> 状态：第一阶段开发基线  
> 产品形态：移动端优先的私人照片记忆 Web App

## 1. 产品定义

### 1.1 一句话定义

片刻是一个长期陪伴用户成长的私人数字记忆空间，帮助用户记录当下、整理过去，并在未来重新遇见曾经的自己。

### 1.2 核心价值

“记录发生过什么，也保存当时的自己。”

片刻不以公开展示、互动增长或内容消费为目标。照片是记忆入口，文字、时间、地点和情绪共同保存事件的上下文。

### 1.3 产品边界

片刻不是：

- 公共相册或摄影作品展示站；
- 博客、朋友圈或社交平台；
- 以点赞、关注和推荐为核心的内容产品；
- 生日纪念页或大量情绪动画组成的短期体验。

片刻必须是：

- 默认私密、以用户本人为唯一默认受众；
- 可以持续使用多年且内容价值随时间增长；
- 记录足够轻，回看足够有情感；
- 数据可靠、可恢复、可导出。

## 2. 目标与衡量指标

### 2.1 产品目标

1. 让用户在 60 秒内完成一条包含照片和文字的记忆。
2. 让用户能通过时间、标签、地点和搜索找回任意记忆。
3. 通过随机回忆、未来信箱和年度总结形成长期回访动力。
4. 以严格的数据隔离和可控分享建立私人日记所需的信任。

### 2.2 北极星指标

每月完成至少一次“记录—回看”闭环的活跃用户数。

### 2.3 辅助指标

- 首条记忆创建完成率；
- 创建一条记忆的中位耗时；
- 7 日、30 日记录留存率；
- 月均有效记忆数；
- 搜索或筛选后的记忆打开率；
- 随机回忆后的停留与再次记录率；
- 数据导出成功率、媒体处理成功率；
- 未授权内容访问事件数（目标为 0）。

## 3. 用户与场景

### 3.1 核心用户

- 希望记录生活但不愿公开表达的人；
- 有大量手机照片，却难以保留照片背后故事的人；
- 希望通过长期记录理解自己变化的人；
- 重视隐私、数据所有权和长期可用性的人。

### 3.2 核心任务

1. 我刚经历了值得记住的一刻，希望快速保存照片与感受。
2. 我想知道某年、某个季节或某个地点发生过什么。
3. 我想找回与“旅行”“朋友”或某种心情有关的记忆。
4. 我想偶然遇见过去的自己，但可以避开不愿回看的内容。
5. 我想给未来的自己留下一封在指定日期打开的信。
6. 我想获得一份克制、有叙事感的年度记忆总结。

## 4. 产品原则

1. **私密优先**：内容默认仅本人可见，分享是明确授权后的例外。
2. **照片优先**：照片承担视觉叙事，文字恢复情绪和语境。
3. **低摩擦记录**：除媒体与正文外，其余字段均可稍后补充。
4. **时间真实**：事件时间与系统创建时间分开保存。
5. **允许反悔**：修改有历史、删除可恢复、归档可撤销、回忆可屏蔽。
6. **长期所有权**：自动备份、开放导出，不以平台锁定用户。
7. **安静设计**：不制造信息焦虑，不使用社交化指标和高刺激反馈。

## 5. 信息架构

### 5.1 一级导航

- **首页**：个人记忆流、随机回忆入口；
- **时间**：时间轴与“我的一年”日历；
- **记录**：创建记忆的主入口；
- **记忆**：标签、地点、情绪及搜索；
- **我的**：账户、归档、回收站、未来信箱、年度总结、备份与设置。

### 5.2 主要对象

- 用户；
- 记忆；
- 媒体文件；
- 标签与情绪；
- 地点；
- 记忆历史版本；
- 临时分享；
- 未来信箱；
- 年度总结；
- 导出与备份任务。

## 6. 功能需求

### 6.1 账户与私人空间（P0）

#### 单一主人账户

- 私人部署默认只创建一个主人账户，不提供公开注册入口；
- 登录页只展示访问密码，不暴露账户邮箱；
- 初始密码为 `20260907`，仅用于首次登录并应立即更换；
- 初始密码和当前密码不得写入网页源码、仓库配置或业务数据库；
- 账户凭据由认证服务以密码哈希形式管理；
- 明确告知“内容默认私密”。

#### 登录与会话

- 支持密码登录、退出及登录后自主修改密码；
- 登录页提供用户协议、隐私政策以及默认私密说明；
- 会话安全存储并可撤销；
- 未登录用户不得进入私人页面；
- 登录后只可访问自己的数据。

#### 密码登录安全

- 登录失败使用统一提示，不区分账户是否存在；
- 连续失败触发服务端限流和冷却时间；
- 修改密码前要求验证当前密码；
- 新密码至少 10 位，且不得与当前密码相同；
- 密码不得写入日志、分析系统、前端配置或本地持久化存储；
- 修改密码后应撤销其他设备的旧会话；
- 高风险或新设备登录可通知用户并允许撤销会话。

#### 验收标准

- 用户 A 无法读取、修改或推断用户 B 的任何内容或媒体地址；
-退出后私人页面和私有资源立即不可访问；
- 错误密码尝试受限流保护且不泄露账户标识；
- 页面源码、部署文件和业务数据库中均不存在明文密码。

### 6.2 创建记忆（P0）

#### 入口

- 首页顶部与移动端底部中央均提供“＋ 记录此刻”；
- 点击后进入全屏或独立创建页。

#### 内容字段

- 1 条记忆可包含多张图片，也可包含视频；
- 正文提示语：“此刻在想什么？”；
- 事件时间默认当前时间，可补录过去；
- 系统独立记录创建时间与更新时间；
- 地点支持手动输入，地图定位为后续增强；
- 情绪支持固定选项和自定义情绪；
- 标签支持自由创建与复用。

#### 图片

- 支持 JPG、PNG、WEBP；
- 默认读取 EXIF 拍摄时间进行排序；
- 缺少 EXIF 时按上传顺序；
- 用户可拖拽手动调整顺序；
- 保留原图，同时生成压缩展示图和缩略图；
- EXIF 仅用于用户授权的产品功能，不公开泄露。

#### 视频

- 单文件不超过 500MB；
- 上传后进入自动转码流程；
- 生成网页播放版本、缩略封面并保留原文件；
- 转码期间记忆可保存为处理中状态；
- 失败后允许重试或移除失败媒体。

#### 草稿与提交

- 第一阶段至少提供离开页面前提醒；
- 后续支持自动草稿；
- 上传和保存过程展示明确进度；
- 重复提交不得生成重复记忆。

#### 验收标准

- 正常网络下，用户可以在 60 秒内创建一条图文记忆；
- 多图顺序保存后与预览一致；
- 事件时间与创建时间分别、正确保存；
- 任何媒体处理失败均有可理解的状态和恢复动作。

### 6.3 首页记忆流（P0）

- 不采用传统数据 Dashboard；
- 按事件时间倒序展示，创建时间仅在必要场景显示；
- 每条卡片以首张媒体为视觉主体；
- 展示日期、地点、简短正文、情绪和少量标签；
- 支持继续加载；
- 点击进入记忆详情；
- 空状态引导用户创建第一条记忆。

### 6.4 记忆详情与修改（P0/P1）

- 完整展示全部媒体、正文、事件时间、地点、情绪和标签；
- 支持修改，修改前内容进入历史版本；
- 历史版本保存结构化字段快照，不重复复制未改变的媒体文件；
- 支持归档、移入回收站、分享和回忆屏蔽；
- 第一阶段完成查看、基础修改和删除入口；版本浏览在第二阶段提供。

### 6.5 删除、回收站与归档（P1）

- 删除操作先进入回收站，不立即物理删除；
- 默认保留 30 天，期限应可配置并在界面明确说明；
- 支持恢复至原状态；
- 到期后执行异步永久删除，并清理无引用媒体；
- 归档内容仍属于用户，可搜索，但默认不出现在首页流；
- 归档和取消归档不改变事件时间。

### 6.6 时间轴（P1）

- 按年份和月份显示记录数量；
- 年、月均可展开或进入对应记录列表；
- 无记录月份不制造视觉噪音；
- 大量数据采用分页或虚拟加载。

### 6.7 “我的一年”日历（P1）

- 选择年份后显示年度日历；
- 有记录的日期显示克制标记；
- 点击日期展示当天全部记忆；
- 以事件发生日期作为归档依据。

### 6.8 标签、地点与情绪（P1）

- 标签页显示标签名称、记录数量和代表性缩略图；
- 点击后查看所有相关记忆；
- 支持标签重命名和合并；
- 固定情绪提供稳定统计维度，自定义情绪保留个人表达；
- 地点可按规范化地点和用户原始文字检索。

### 6.9 搜索（P1/P2）

#### 第一层：结构化搜索

- 全文：正文；
- 标签；
- 地点；
- 日期范围；
- 情绪；
- 媒体类型。

#### 第二层：AI 语义搜索

- 支持“去年夏天和朋友去海边的照片”等自然语言查询；
- 可基于用户授权后的正文、标签和图片描述建立向量索引；
- 索引必须携带用户标识并受同等权限策略保护；
- 明确区分搜索结果与 AI 推断；
- 提供关闭 AI 索引和删除已生成索引的能力。

### 6.10 随机回忆（P2）

- 入口文案：“遇见过去的自己”；
- 支持“三年前的今天”、同季节、普通随机等策略；
- 避免短期内重复出现同一条；
- 已归档、回收站、被屏蔽内容不参与推荐；
- 用户可对单条记忆选择“不再主动提醒”；
- 对可能敏感的记忆保持克制，不进行未经授权的情绪判断。

### 6.11 未来信箱（P2）

- 输入文字，可选附加媒体；
- 设置开启日期；
- 未到期时仅展示创建日期、倒计时和信件状态，不显示内容；
- 到期后由用户主动开启；
- 允许在开启前删除，是否允许修改需在创建时明确；默认创建后不可修改正文。

### 6.12 年度总结（P2）

- 每年自动生成一次，可手动重新生成；
- 统计记忆数、照片数、地点、常用标签和高频词；
- 形成以叙事为主、统计为辅的年度记忆册；
- 发布给用户前允许隐藏敏感记忆；
- 支持导出 PDF；
- 自动生成失败不得影响原始记忆数据。

### 6.13 临时分享（P1）

- 默认不分享；
- 用户主动生成高随机度临时链接；
- 可设置有效期、是否允许下载、访问密码；
- 可随时撤销；
- 链接访问者只可查看被授权的单条记忆及媒体；
- 页面不被搜索引擎索引；
- 访问日志遵循最小化收集原则。

### 6.14 备份与导出（P2）

- 系统自动备份数据库及媒体元数据；
- 明确区分灾难恢复备份和用户回收站；
- 用户可导出结构化数据和媒体文件；
- 导出采用异步任务，完成后生成限时下载链接；
- 导出内容包含事件时间、文字、标签、地点和原始媒体。

## 7. 关键交互状态

每个核心页面必须覆盖：加载、空内容、部分失败、无网络、无权限、成功和可重试状态。

创建页尤其需要：

- 媒体选择中；
- 上传中；
- 图片处理中；
- 视频转码中；
- 部分媒体失败；
- 保存成功；
- 离开时存在未保存修改。

## 8. 视觉与内容规范

### 8.1 视觉方向

- 背景：`#F7F5F2`；
- 正文：`#222222`；
- 辅助文字使用低对比中性灰；
- 标题使用克制的 Serif 字体，正文使用易读 Sans-serif；
- 卡片圆角、轻微阴影、留白充足；
- 避免高饱和强调色、大量装饰动画和社交媒体式密集信息。

### 8.2 内容语气

- 温暖但不煽情；
- 像一本私人日记，而不是系统后台；
- 使用“记录”“遇见”“那一天”等具有人情味的词；
- 错误提示说明发生了什么、内容是否安全、用户接下来能做什么。

## 9. 非功能需求

### 9.1 隐私与安全

- PostgreSQL 行级安全覆盖所有用户内容表；
- 私有媒体桶，不暴露永久公共 URL；
- 下载与展示使用短期签名 URL；
- 服务端操作再次校验资源归属；
- 分享令牌只保存哈希值；
- 重要操作记录审计事件；
- 日志不得写入正文、信件内容或长期有效媒体地址。

### 9.2 性能

- 首屏优先加载缩略图或压缩图；
- 首页首批建议 10–20 条记忆；
- 原图延迟加载；
- 大文件采用可恢复上传；
- 图片处理和视频转码异步执行。

### 9.3 可用性与无障碍

- 响应式支持手机和桌面浏览器；
- 核心功能可通过键盘完成；
- 颜色对比满足 WCAG AA；
- 图片允许填写替代文字；
- 动效尊重“减少动态效果”系统设置。

### 9.4 数据一致性

- 数据库只保存媒体对象键，不保存不可控永久链接；
- 创建记忆与媒体关联采用幂等流程；
- 事件时间统一保存时区信息或 UTC 加原始时区；
- 软删除、物理删除和备份清理分别管理。

## 10. 第一阶段范围

### 10.1 必须完成

- 邮箱注册、登录、退出和密码重置；
- 私人账户与行级数据隔离；
- 多图片上传，原图/展示图/缩略图处理链路；
- 创建、查看、基础修改记忆；
- 事件时间、地点、固定情绪、自定义标签；
- 首页个人记忆流；
- 基础归档与回收站数据字段；
- 响应式移动端导航；
- 基础错误、空状态与上传进度。

### 10.2 暂不进入第一阶段

- 视频转码；
- 地图定位；
- 历史版本浏览界面；
- 时间轴、年度日历；
- AI 搜索；
- 随机回忆、未来信箱、年度总结；
- 分享链接与用户导出。

数据库可提前为这些能力预留结构，但不在第一阶段暴露未完成入口。

## 11. 第一阶段用户流程

### 11.1 首次使用

注册 → 邮箱验证 → 登录 → 空首页 → 点击“记录此刻” → 上传照片 → 输入文字和元数据 → 保存 → 返回首页看到新记忆。

### 11.2 日常记录

登录 → 首页 → “＋” → 选择多张图片 → 检查顺序 → 输入文字 → 选择情绪/标签 → 保存。

### 11.3 修改与删除

首页 → 记忆详情 → 编辑 → 保存并生成历史版本；或移入回收站 → 在“我的／回收站”恢复。

## 12. 里程碑与发布门槛

### 里程碑 A：工程与安全基线

- Next.js、Supabase 与环境配置；
- 数据库迁移和 RLS 自动化测试；
- 认证流程与受保护路由。

### 里程碑 B：记录闭环

- 上传与媒体处理；
- 创建、查看、修改、软删除；
- 首页记忆流。

### 里程碑 C：可发布质量

- 移动端与桌面端体验；
- 异常和空状态；
- 性能、无障碍和安全检查；
- 备份恢复演练与隐私说明。

### 第一阶段发布门槛

- 账户间越权测试全部通过；
- 关键创建流程端到端测试通过；
- 图片上传失败可恢复且不产生孤儿公开文件；
- 手机端核心页面无阻断性布局问题；
- 回收站恢复可用；
- 隐私默认值和用户文案完成审查。

## 13. 风险与决策记录

| 风险 | 影响 | 当前决策 |
|---|---|---|
| 长期媒体成本 | 原图和衍生文件持续增长 | 分层存储、配额与生命周期策略后续确定 |
| 视频处理复杂 | 500MB 上传及转码失败率高 | 第一阶段不开放视频，保留模型与接口 |
| EXIF 时间不可靠 | 截图、编辑图可能缺失或错误 | EXIF 仅作默认排序，允许手动调整 |
| AI 搜索隐私 | 索引可能扩大数据暴露面 | 独立授权、用户级隔离、可关闭和删除 |
| 随机回忆触发负面情绪 | 损害信任 | 单条屏蔽、归档排除、避免敏感推断 |
| 分享破坏默认私密 | 链接泄露 | 限时、可撤销、最小权限、令牌哈希 |
